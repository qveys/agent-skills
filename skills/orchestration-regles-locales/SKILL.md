# Règles locales d'orchestration Orca (Quentin)

S'appliquent à tout coordinateur Orca, en plus du skill `orchestration`. Ce skill n'est pas géré par `orca skills update`.

- **Nettoyage obligatoire** : dès qu'un `worker_done` est reçu, validé et que le worker n'a plus rien à faire, `worker-release --dispatch <id>` immédiatement. Ne pas attendre la fin du run. Inclut les échecs réglés (`failed` + `retained` ou `reclaimable`). Seul un worker explicitement gardé à la demande de Quentin reste (`worker-retain`).
- **Fin de tour** : `worker-list --run <run> --terminal-state reclaimable` doit être vide ; vérifier aussi les `retained` non voulus.
- **Vérifier les agents disponibles, une fois par run, sans quota LLM** : inventaire fait une seule fois à la création du run (pas par worker), jamais par prompt de test. Binaire présent (`command -v` ; id Orca `antigravity` = binaire `agy`), puis quota lu hors LLM, par agent : `claude` = `claude auth status` (connexion) ; `codex` = `codex login status` + dernier `"rate_limits"` `used_percent` des jsonl `~/Library/Application Support/orca/codex-accounts/*/home/sessions/**` (date de la dernière session) ; `agy` = `agy -p /usage --output-format json` (0 token ; seulement si `agy --version` ≥ 1.1.11, sinon `/usage` part comme prompt et brûle du quota) → `remaining_fraction` par groupe/fenêtre ; `grok` = GET `https://cli-chat-proxy.grok.com/v1/billing?format=credits` avec `Bearer` = clé de `~/.grok/auth.json` (token expire en quelques heures, lancer `grok` pour le rafraîchir) → `creditUsagePercent` ; `muse` = token Keychain `security find-generic-password -s ai.meta.dev.credentials -w` (JSON, champ `access_token` ; invite macOS à valider par Quentin, ne jamais afficher le token) puis POST `https://api.meta.ai/muse-code/key` (en-têtes `x-api-version: 1.0.0`, corps `{"onboard": false}`) → `subs_usage.window` (5 h) et `.weekly` en `used_percent` ; `opencode` = aucune lecture gratuite (ne rien installer : peut être configuré sur un autre modèle) → « inconnu », reste dans la liste. Exclure du tirage un agent à ≥ 90 % utilisé sur une fenêtre. Mémoriser la liste pour le run. Un worker qui échoue sur quota/clé expirée/non connecté (`quota exhausted`, `API key has expired`, `not signed in`) retire cet agent de la liste pour le reste du run, puis retry avec un autre agent tiré au hasard.
- **Exclusions persistantes** : fichier d'état `~/.agents/skills/orchestration-regles-locales/agents-exclus.json` (`{"<agent>": "<date ISO de fin>"}`). Au début de l'inventaire, le lire et ignorer tout agent dont la date de fin est future ; purger les dates passées. Un worker `opencode` (ou autre) qui échoue ne renvoie pas de `worker_done` : après `worker-start`, lire `worker-read --dispatch <id>` pour détecter `quota ... exhausted` / `will reset at <MM-JJ HH:MM:SS UTC>` (année = courante, ou suivante si la date est passée) → écrire cette date ; `API key has expired` / `not signed in` (sans date) → exclusion de 24 h. Puis `worker-stop` + `worker-release` et retry sur un autre agent tiré au hasard.
- **Workers aléatoires et variés (obligatoire)** : choisir l'agent de chaque worker au hasard parmi les agents vérifiés (`claude`, `codex`, `antigravity`, `grok`, `muse`, `opencode`…), jamais toujours le même ni par habitude (ex. `shuf -n1`). Répartir un lot sur plusieurs fournisseurs ; ne pas répéter le même agent pour deux workers consécutifs tant que d'autres sont disponibles. Adapter `--model`/`--effort` à la tâche (voir mémoire `orca-worker-model-effort-par-tache`) ; un agent sans support (ex. Grok) = sans ces options. Exception : agent imposé par Quentin.
- **Reprise d'un run** : `run-use --id <run>` (le run peut être « fenced » par un autre coordinateur).
- **Retry** : `worker-start --task <id> --terminal=<handle> --worktree current --retry-of <dispatch>` (syntaxe `--terminal=<handle>` avec `=`).
- **Harnais GitHub** : chaque brief impose `PATH=/usr/local/libexec/claude-gh-harness/bin:$PATH` ; jamais git/gh natif (demandes 1Password).
